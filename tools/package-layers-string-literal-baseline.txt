# Package-layers string-literal FQCN baseline (PL008) — see bin/check-package-layers.
#
# Format: one entry per allowlisted file (relative to packages/), followed by
# two or more spaces and a mandatory rationale comment:
#
#   <pkg>/src/Path/To/File.php  # reason why the string-literal FQCNs are legitimate
#
# Meaning: the listed file contains quoted Waaseyaa\<Ns>\… FQCN string literals that
# reference packages at a higher layer than the containing package. These are accepted
# because the file is a discovery bootstrapper or kernel-level orchestrator that cannot
# use `use` imports (which would be upward PL005 violations) and instead encodes FQCNs
# as string constants per the CLAUDE.md "Layer discipline for imports" rule:
#   "When cross-layer attribute scanning is needed, use string constants instead of
#    ::class references. ReflectionClass::getAttributes() accepts string class names."
#
# Add new entries here (with rationale) when a legitimate cross-layer FQCN is
# introduced in any layer. Do NOT add entries to hide accidental coupling —
# fix the coupling instead (e.g. move the route registration to the owning provider).
#
# IMPORTANT: baselining is per-FILE, not per-finding — an entry suppresses EVERY
# PL008 finding in that file, including unrelated upward references smuggled in
# later. Before adding or keeping an entry, re-audit the ENTIRE file for upward
# references, not just the finding that prompted the entry.
#
# Known false-positive class: a human-readable diagnostic/exception message that
# merely MENTIONS a higher-layer FQCN (e.g. "expected an instance compatible with
# Waaseyaa\Node\NodeInterface") trips sub-pattern (a) even though it is not runtime
# coupling. Prefer rephrasing the message (drop the namespace, use the short name);
# baseline the file only if the FQCN genuinely helps the operator.
#
# New PL008 violations NOT listed here fail CI (fail-on-new).
#
