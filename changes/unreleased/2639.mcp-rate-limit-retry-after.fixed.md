- **Fixed — MCP rate-limit refusals now carry a `Retry-After` header (#2639):** the 429 response for `RATE_LIMIT_EXCEEDED` sets `Retry-After` to the same window-seconds value already carried in `error.data.retry_after_seconds`, so a generic HTTP client or intermediary backs off correctly without parsing the JSON-RPC body. The `RATE_LIMITER_UNAVAILABLE` 503 is unchanged -- its retry semantics remain undefined.
