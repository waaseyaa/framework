- **Workflow transition discovery and execution now resolve the same workflow
  position (#2836).** `TransitionService::transition()` deliberately judges
  legality from the repository WORKING COPY, but
  `TransitionService::getAvailableTransitions()` — documented as the one
  sanctioned read side for UIs — read the state straight off the passed
  object. For published content carrying a forward draft, a served `find()`
  snapshot therefore advertised the published pointer's outgoing edges while
  execution rejected them as `REASON_ILLEGAL_EDGE` from the draft tip's real
  state. Every in-tree caller masked the split by pre-loading the tip
  (`WorkflowTransitionController`, `WorkflowAuthorityVisibility`,
  `ContentPublisher`), but `WorkflowContentPublicationTransitioner` passes its
  argument through untouched, so the public publishing bridge was exposed.

  Both paths now resolve the basis through one private helper, which guards a
  null/empty entity id and degrades to the passed object when no repository or
  no working copy resolves — the same fallback
  `WorkflowStateGuard::workingCopyBasis()` already used. No public signature or
  return shape changed, and callers that already pre-load the tip see the
  identical list. Proofs:
  `packages/workflows/tests/Unit/Transition/TransitionServiceTest.php` covers a
  served snapshot that differs from the working copy, the working copy passed
  in directly, the no-working-copy fallback, and discovery-then-execution
  agreement on one offered transition.
