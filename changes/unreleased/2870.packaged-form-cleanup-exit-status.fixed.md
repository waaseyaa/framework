- **Fixed — `tests/PackagedForm/check-*` teardown can no longer overwrite a passed proof's exit status (#2870):** each of the twelve `check-*` scripts under `tests/PackagedForm/` installed `trap cleanup EXIT` with a bare `rm -rf -- "$work"`; under `set -euo pipefail` a cleanup-time removal failure (a lingering process, a filesystem race against something the proof itself just created) is itself an error, and that error's exit status silently became the *script's* exit status, overwriting a proof that had already fully passed. `cleanup()` now guards the removal with `rm -rf -- "$work" || echo "warning: failed to remove $work" >&2`, carrying an inline comment stating the invariant, so a failed teardown is reported on stderr instead of corrupting the result — while an explicit failure path elsewhere in the script (e.g. `exit 1`) still propagates unchanged. `check-consumer-key-hygiene` has no such trap and was left alone. `tests/Architecture/PackagedFormCleanupExitStatusTest.php` locks the shape going forward: it rosters every script carrying `trap cleanup EXIT` (a new one not on the roster fails the test), asserts each rostered cleanup neutralizes its exit status while still reporting a leak, and carries a runnable negative control that executes the exact pre-fix shape against a work directory whose removal genuinely fails, proving it really does corrupt a successful exit.
