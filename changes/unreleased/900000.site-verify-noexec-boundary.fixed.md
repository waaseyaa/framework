- **Fixed — measure generated site-verify runnability without relying on a mount's execute-bit policy (#900000 — PLACEHOLDER, no GitHub issue filed yet; assign a real issue before opening a governed PR):** the generated `tests/Acceptance/SiteGoldenPathTest.php` acceptance test asserted `is_executable()` on the generated `bin/maintenance/site-verify` command, which reports false for a genuinely mode-0755 file whenever the project tree is mounted noexec (e.g. inside a hardened execution sandbox), refusing verification with no way to pass. The generated test now measures two properties separately: the artifact's POSIX permission bits via `fileperms()` (mount-independent, still fails if Framework ever stops chmod-ing the artifact), and that the command actually runs through the supported `PHP_BINARY <script>` invocation via a `--self-test` short-circuit, rather than trusting a shebang-prefix string alone.

  Bounded to `packages/site-contract/src/Generation/SiteArtifactRenderer.php`. No production caller invokes the generated command by direct execve — `.ci/site-verify.php`, the skeleton's `composer.json` `site-verify` script, and the `.ci/site-verify` shell wrapper all reach it through `PHP_BINARY`/`@php`, so this repair introduces no invocation-contract change for existing consumers.
