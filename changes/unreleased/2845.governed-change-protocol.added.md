- **Added — ADR-025 names the governed-change protocol and its change-receipt envelope (#2845, ADR-025 D-14):** the artifact-plan decision previously fixed plan, preview, apply and recovery semantics for generation alone, leaving open whether schema migration (#1625/#2730/#2731) — which owns its own planner, executor and ledger — speaks the same lifecycle language. D-14 names those semantics as a domain-neutral contract of seven obligations (immutable digest-bound plan, side-effect-free preview, stale-plan detection, controlled apply, typed change receipt, verification, recovery) and fixes a closed receipt envelope (`receipt_id`, `protocol_version`, `authority`, `authority_version`, `operation`, `plan_digest`, `outcome`, `correlation_id`, `causation_receipt_id`, `recorded_at`, `domain_payload`) with an `applied`/`no_op`/`refused`/`failed`/`recovered` outcome vocabulary. Preview emits no receipt; a recovery that precedes new work emits two causally chained receipts rather than collapsing into one. Correlation groups related work without implying a distributed transaction or cross-authority rollback, and a composite orchestrator may reference child outcomes but may never overwrite or restate them. "One durable ownership record" is fixed as one authoritative record *per lifecycle boundary*, so the existing audit, validation, migration and generated-state records stay separate where their ownership is explicit and non-overlapping. D-14.7 binds `ArtifactApplyResult` as the sole authorized binding, mapping its existing members under `domain_payload` and recording receipts to an append-only `.waaseyaa/receipts.jsonl` that is evidence and never an authority: written after the transaction terminates, never read to make a decision, and reconciled against `.waaseyaa/generated.json` when a crash loses the last append. D-14.6 separates the new **change** receipt from ADR-023's existing **decision** receipt, which records approval rather than outcome. No schema binding, shared runtime code, or new package is authorized: D-14.8 requires a second real implementation before any abstraction is extracted, and states the conformance checklist that binding must satisfy.
