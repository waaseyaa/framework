- **Added — a conformant local stdio MCP server, `mcp:serve --profile=developer` (#2659, ADR-022 D-9.2):** a coding agent can now start the approved Waaseyaa developer catalogue over local stdio, no HTTP and no OAuth. The command speaks newline-delimited JSON-RPC 2.0 (`initialize`, `ping`, `tools/list`, `tools/call`) directly on stdin/stdout — every diagnostic, including a refused local-operator attestation, goes to stderr as a structured JSON line, and a real subprocess conformance test (`tests/Integration/Mcp/StdioMcpConformanceTest.php`) asserts every byte on stdout parses as a JSON-RPC frame. It reuses the transport-neutral dispatch extracted in #2657 (`AgentToolDispatcher` / `AuditedToolDispatcher`) rather than forking it, constructs its acting identity through the #2658 `LocalOperatorPrincipal` attestation, and narrows the framework tool registry to the principal's D-7 default allowlist with `ToolIdAllowlistRegistry`. Every `tools/call` reserves and finalizes a `strict_audit_ledger` row under the dedicated surface `waaseyaa.local.stdio` (never `mcp`/`mcp.*`) with one transport-owned request correlation id and a `null` actor uid; real SQLite integration tests prove that the same id reaches sanitized failure responses, safe logs, reservations, and finalizations for both thrown tools and output-schema violations. `mcp:serve` is registered by a new `waaseyaa/cli` provider gated on `waaseyaa/ai-agent` via the same `RequiresOptionalPackagesInterface` mechanism #2826 introduced for `ai:*` — `waaseyaa/cli` still only `suggest`s `ai-agent` (never `require`s it, preserving CP009), so a `--no-dev` consumer without the local AI-development plane sees zero `mcp:*` commands. `waaseyaa/ai-tools`, where the dispatch contracts live, becomes a direct (non-optional) `require` of `waaseyaa/cli`; it was already production-present in `waaseyaa/framework` and `waaseyaa/full`, so this adds no new production dependency edge. A `StdioServerExecutableResolver` proves cross-platform executable resolution on both POSIX and Windows path shapes, always via `PHP_BINARY` or an injected override and never a bare `'php'`; portable launcher generation is explicitly transferred to #2663. Official MCP Inspector 2.5.0 completed strict `tools/list` against the packaged command. The official PHP SDK v0.8.1 was evaluated but not adopted because its pre-1.0 Tier-3 status and current package placement would make a developer-only transport dependency production-present; the re-evaluation triggers are recorded in `docs/specs/ai-integration.md`. Also deferred: two of the three D-7 default tools (`bimaaji_introspect_graph`, `bimaaji_introspect_section`) need `Waaseyaa\Bimaaji\Graph\ApplicationGraphGenerator`'s routing-introspection dependency, which `ConsoleKernel` does not bind — a pre-existing kernel-wiring gap, not a #2659 regression, documented in `docs/specs/ai-integration.md`.
