- **Fixed — `make:policy` and `scaffold:workflow` now render real, canonical governance artifacts instead of an invalid stub and unhydratable JSON (#2848):** the pre-existing `make:policy` stub claimed `implements AccessPolicyInterface` while rendering `view()`/`create()`/`update()`/`delete()` methods — the real interface requires `access()`/`createAccess()`/`appliesTo()`, so the generated class would fatal if ever loaded. `MakePolicyHandler` now requires `--entity=<id>` and accepts repeatable `--grant=<operation>:<permission>` (and an optional `--entity-class=` override), and renders through the new public `AccessPolicyEmitter::renderPolicyClass()` — the same code path the blueprint compiler (#2788) already uses — so a manual invocation and an equivalent blueprint `policies:` declaration converge on the same `#[PolicyAttribute]`-annotated, explicitly granted entity-policy shape. Zero `--grant`s still renders a valid, entity-bound, all-`Neutral` class rather than a broken one. Separately, `scaffold:workflow`'s JSON could not hydrate a real `Waaseyaa\Workflows\Workflow` (no `label`/`published`/`default_revision`/`initial_state`) and had no `--entity-type`, so its `--bundle` alone could never form a valid `workflows.assignments` key. `WorkflowScaffoldHandler` now requires `--entity-type` alongside `--bundle`, accepts an optional `--initial-state`, and renders through the new public `WorkflowDefinitionEmitter::toDefinitionArray()` (same `default_revision := published` / sort-by-id derivation the blueprint compiler's PHP-source renderer already documents), emitting `{"workflow": <Workflow hydration array>, "assignment": {"<entity_type>.<bundle>": "<id>"}}`. Both commands stay stdout-only with zero side effects (ADR-025 D-4's existing `keep` disposition is unchanged); neither writes a file, activates a Composer provider, or touches the staged #2846 generation-unit authority (#2857 remains root's separately tracked activation gap). `AccessPolicyEmitter`/`WorkflowDefinitionEmitter`'s existing blueprint-compiled golden-byte output is unchanged — the policy path reuses the existing renderer, and PHP/JSON workflow serializers share one canonical definition transformation. Output alone does not prove application registration; packaged enforcement remains tracked in FW-GOVERNANCE-SCAFFOLD-CONVERGENCE-01.
