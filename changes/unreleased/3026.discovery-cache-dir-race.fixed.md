- **Fixed — discovery cache-directory creation tolerates a competing creator (#3026):** `PackageManifestCompiler::compileAndCache()` treated a directory another process created between its existence check and its own `mkdir()` call as a real failure, throwing even though the cache write would have succeeded; it now rechecks `is_dir()` after a failed `mkdir()` (the idiom already used at 8+ other first-party call sites), so only a genuine creation failure — no directory afterward, or a regular file occupying the path — still throws, and write/rename failure visibility is unchanged.
