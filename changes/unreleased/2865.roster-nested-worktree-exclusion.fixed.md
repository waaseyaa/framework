- **Fixed — the S1 roster gates no longer scan nested worktrees or nested `tmp/` build caches as production source (#2865):** `s1RosterIsExcluded()` (`bin/lib/s1-roster.php`) excluded `vendor/` and `node_modules/` at any depth but `tmp/` only at the repository root, and did not exclude `.claude/worktrees/` at all — so with one nested git worktree present, a different checkout's PHPStan cache (`.claude/worktrees/*/tmp/phpstan*/resultCache.php`) was read as a governed SQLite-construction and schema-boundary candidate, failing `check-s1-sqlite-contract` and `check-s1-schema-authority` in the primary working tree while passing in CI, which checks out one tree and has no nested worktrees. That is exactly the local/CI divergence the function's docblock says the any-depth `vendor/` rule exists to prevent (`docs/specs/governed-gates.md` invariant 5), and because `bin/check-pr-preflight` is the pre-push hook it made the hook unusable and `--no-verify` the routine escape. `tmp/` is now excluded at any depth, matching `vendor/` and `node_modules/`, and `.claude/worktrees/` is excluded outright. `.claude/` itself stays scannable — `.claude/rules/*.md` and `.claude/settings.json` are tracked content — and `S1RosterLibraryTest` now asserts both directions: nested `tmp/` and nested-worktree paths contribute no candidates, and a tracked `.claude/` file still does. No roster regeneration was required, because the removed candidates were never legitimate: `support/s1-sqlite-construction-roster.json` and `support/s1-schema-authority-roster.json` are unchanged.
