- **The warn-only composer-dependency audit no longer carries ignores that never apply (#2969).** `composer-dependency-analyser.php` had 11 configured suppressions the tool itself reported as "never occurred" — its own signal that the condition each was written to silence no longer exists. Four `UNUSED_DEPENDENCY` entries (`waaseyaa/analytics`, `deployer`, `engagement`, `github`) were obsolete because each package now has real usage confined to `isDev:true`-scanned paths (its own test suite), which the tool classifies as `PROD_DEPENDENCY_ONLY_IN_DEV` instead — a different error type the removed block never suppressed, so those three now show correctly among the live "prod dependency used only in dev paths" findings, and `engagement`, already declared `require-dev`, is now fully compliant with no finding at all. One `SHADOW_DEPENDENCY` entry (`symfony/dependency-injection`) was obsolete because the package has zero code references anywhere, in either scan partition. Five `PROD_DEPENDENCY_ONLY_IN_DEV` entries (`symfony/dotenv`, `waaseyaa/groups`, `waaseyaa/node`, `waaseyaa/state`) resolved to fully compliant production usage — `waaseyaa/state` specifically via a same-package internal `use` import inside its own `isDev:false`-scanned `src/`, which the tool counts as production usage regardless of the importer's package — and `waaseyaa/messaging` moved to `require-dev`, making that error type structurally inapplicable to it (it now correctly surfaces instead, unaffected by this change, under the live and unrelated `DEV_DEPENDENCY_IN_PROD` finding). One unknown-class entry (`Waaseyaa\Entity\Storage\SqlEntityStorage`) was obsolete because the class has zero definitions and zero references left anywhere; its sibling `Waaseyaa\Database\PdoDatabase` is still referenced and is retained unchanged. Each removal was established from AST-usage evidence mirroring the tool's own `isDev` path partition, not from the "never occurred" line alone, and the now-empty `UNUSED_DEPENDENCY` block is removed in full rather than left as a no-op call. A full before/after run confirms the live finding set is byte-for-byte identical in content, order and category counts (36 unknown classes, 1 unknown function, 8 shadow dependencies, 8 dev dependencies in production code, 6 prod-dependency-only-in-dev, 1 unused dependency) — only the 11 stale "never occurred" lines are gone. The job remains warn-only and outside `composer verify`; the live `waaseyaa/telescope` unused-dependency finding and the six root requires flagged for `require-dev` are unchanged and explicitly out of scope.
