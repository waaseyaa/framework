- **Fixed — isolate the generated site-verify command's PHPUnit result cache under `storage/` (#3056):** the generated `bin/maintenance/site-verify` command ran `vendor/bin/phpunit` with no `--cache-directory` override, so PHPUnit fell back to `phpunit.xml.dist`'s `cacheDirectory=".phpunit.cache"` and wrote `test-run-history` (real wall-clock test timings) at the PROJECT ROOT on every verification run. Any consumer that treats a materialized project tree as a reproducible artifact set (e.g. a byte-equality check comparing two verification runs of the same reviewed plan) observed a spurious, always-differing file, because the timings genuinely differ run to run even when nothing else in the project changed.

  The generated command now passes `--cache-directory=<project-root>/storage/.phpunit.cache`, which is already excluded as ephemeral runtime state by the skeleton's own `.gitignore` (alongside `vendor/`). No non-deterministic artifact is produced anywhere a reproducibility check inspects, instead of being produced and then filtered out after the fact.

  Bounded to `packages/site-contract/src/Generation/SiteArtifactRenderer.php` and its tests. The byte-frozen generation fixtures that embed the changed artifact's literal content or hashes (site-contract's `blueprint-free-v1` fixture, the cli package's `root-doctor-report` and `BlueprintProcess` process-snapshot fixtures) are regenerated to match; no other bytes in those fixtures changed.
