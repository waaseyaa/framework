- **Added — shared boot-time permission catalogue authority (#2788, FW-SITE-BLUEPRINT-01E review gap G1):** a new Foundation provider capability, `Waaseyaa\Foundation\ServiceProvider\Capability\ProvidesPermissionsInterface` (`permissions(): array<string, array{title, description}>`), lets a package or application contribute permission definitions the same way `ProvidesRolesInterface` contributes roles. `Waaseyaa\Access\PermissionHandler::fromProviders()` composes one deterministic catalogue from the compiled manifest's `extra.waaseyaa.permissions` entries plus every contributing provider, failing closed (`LogicException`) on a duplicate or empty id. `Waaseyaa\User\RoleRepository::assertPermissionsCatalogued()` names every provider-declared role grant the catalogue does not know. `AbstractKernel::boot()` now composes that catalogue after providers boot, refuses to boot (`RuntimeException`) when any `ProvidesRolesInterface` role grants an uncatalogued permission, exposes it as `permissionCatalogue()`, and binds it in the handler container as `Waaseyaa\Access\PermissionHandlerInterface`, so `permission:list` reads the same instance the role validation ran against. The generated `App\Provider\ApplicationBlueprintGovernanceServiceProvider` now implements the capability and returns `ApplicationBlueprintPermissions::seed()`, and is emitted whenever a blueprint declares permissions, roles, or workflows — a blueprint permission unknown to the catalogue can no longer reach an account silently. Proven by the new `tests/Integration/PermissionCatalogue` real-kernel boot proof and unit/emitter tests.
