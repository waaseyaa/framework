- **`health:report` boots in a consumer application without an application-local
  binding (#2820).** `HealthSchemaServiceProvider` published the `health:report`
  command but never bound `HealthReportHandler` itself. In the monorepo this
  went unnoticed because nothing forced resolution through the reflection
  auto-wiring fallback; in a normal consumer application (`waaseyaa/core` etc.),
  the handler container fell through to reflection-based auto-wiring, which
  cannot resolve the handler's plain `string $projectRoot` constructor
  parameter: `Cannot auto-wire "Waaseyaa\CLI\Handler\HealthReportHandler":
  unresolvable parameter "$projectRoot"`.

  `HealthSchemaServiceProvider` now binds `HealthReportHandler` as a singleton,
  following the existing `FieldAccessPreflightHandler` binding in the same
  provider — the project root comes from the framework composition contract
  (`ServiceProvider::$projectRoot`), so no application-local container binding
  or handler subclass is required.
