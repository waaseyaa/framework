- **Fixed — one fail-closed permission admission for every manifest source (#2788, FW-SITE-BLUEPRINT-01E follow-up review):** `PackageManifestCompiler` now admits `extra.waaseyaa.permissions` for installed packages and the root application, on a fresh compile and on a cache reload, through a single sequence: a catalogue that is not an object keyed by id, an invalid id, or a malformed definition (non-array, missing/non-string/empty `title`, non-string `description`, unknown member) is refused with `MalformedPermissionManifestException` naming the owning source instead of being silently skipped or coerced; and an id another source already owns is refused as `PermissionManifestCollisionException` naming the existing owner first, decided BEFORE the redeclared definition is inspected, so a malformed package or root redeclaration cannot bypass duplicate refusal. On a cache reload the root application's own entries re-merge only when byte-identical to the cached manifest; a differing definition is refused rather than overwritten, and a changed root `composer.json` still invalidates the cache and recompiles through the same admission. The closed shape lives in one foundation authority, `PermissionDefinitionShape`, which `PermissionHandler::fromProviders()` now also consults, so provider contributions and manifest entries report identical owner-grounded diagnostics. Valid manifests keep their canonical bytes, fingerprint, and cache read/write behaviour.
