- **Added — ADR-025 authorizes declared additive successor evolution of a generation unit's path set (#2845, ADR-025 D-2.3a):** D-2.3 step 7 previously froze every unit's path set outright, with retire-then-recreate as the only sanctioned answer. That refused ordinary evolution of an authored declaration forever — adding one content type to an initialized `.waaseyaa/site.yaml` is already refused today (D-2.8), and #2787's acceptance requires a changed blueprint to produce an exact reviewable diff, which a frozen set makes impossible without deleting and rewriting every file the application owns. D-2.3a separates fail-closed *ownership* (kept) from fail-closed *evolution* (withdrawn), splitting the authorization across the two halves D-6 already separates so that plan purity survives: the compiler declares capability with a new pure `set_evolution` (`frozen` | `additive`) plan member, and evaluation — the only half that may observe a project — computes the comparison as `EvaluatedArtifactPlan::$setDelta`. No new digest is introduced: the recorded set is already inside `ProjectStateIdentity`, so a successor plan compiled against a generation that has since moved is refused by the `GEN005_STALE_PLAN` recomputation D-6.5 already performs under the exclusive lock. Eligibility is a closed list rather than a field a compiler may set for itself: only the root `site` compiler — the `SiteArtifactRenderer`-composed manifest render, and once #2787 lands the approved-blueprint root compiler — may emit `additive`, every `make:*`/`scaffold:*`/non-root compiler stays `frozen`, and #2846 carries the architecture test asserting that list beside the one asserting the closed `seeded` allowlist. Growth against a `frozen` plan, growth from an ineligible compiler, and any drop from an evolving unit are the new `GEN011_UNAUTHORIZED_SET_DELTA`; shrinking a unit remains retirement-only, explicit and journaled. Every added path faces the full first-publish admission checks (`GEN001`/`GEN002` safety, `GEN003`/`GEN010` ownership, unmanaged-file collision refusal with no override), and carried-forward paths keep their managed-digest and extension-region checks unchanged. There is no flag and no `--force`: a plan may add paths because its compiler declared it and evaluation verified it, not because an operator asserted an override. This closes the additive half of D-2.8; the subtractive half stays refused, because a correct removal must decide the fate of the removed file's contents and that belongs to its own decision.
