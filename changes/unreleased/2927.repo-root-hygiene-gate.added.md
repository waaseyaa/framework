- **Added — `bin/check-repo-root-hygiene`, a repository-root hygiene gate that sees what `git status` cannot (#2927):** 734 stray runtime/test artifacts (~11 MB) had accumulated in the framework repository root undetected — 363 of them were *empty* `waaseyaa_loader_test_*` directories, which `git status` never reports, and the rest were hidden by `.gitignore` leak-family rules. The new gate enumerates the literal filesystem and fails when the root holds any entry that is neither Git-tracked nor on an explicit, source-annotated allowlist of expected local entries (`vendor/`, `tmp/`, `build/`, worktrees, tool caches, IDE and agent-CLI directories, CI evidence); every gitignored leak family is deliberately still a finding. It is registered in `tools/preflight-gates.json` (default profile, so pre-push runs it), enforced in `ci/composer-policy` on the pristine checkout and again after every PHPUnit and random-order shard so a leaking test fails the run that leaked, and proven against fixture repositories by `tests/Architecture/CheckRepoRootHygieneGateTest.php`. The producer trace is recorded in `docs/specs/governed-gates.md` §7: the reproducible mechanism is a relative `TMPDIR` (PHP returns `sys_get_temp_dir() === '.'` verbatim, so every `sys_get_temp_dir() . '/waaseyaa_*_'` scratch helper writes into the checkout), and `tests/bootstrap.php` now refuses to start the suite under a non-absolute or repository-root temp directory (`tests/Support/TempDirGuard.php`). `.gitignore`'s "see #TODO" comment on the leak-family block now cites #2927 and the previously un-ignored `waaseyaa_loader_test_*` family joins it. The gate spawns git with the repository-selecting environment (`GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, `GIT_COMMON_DIR`, and the rest of git's `local_repo_env`) scrubbed, so a pre-push hook run from a linked worktree — which exports `GIT_DIR` — still gates the repository it was given rather than the hook's.
