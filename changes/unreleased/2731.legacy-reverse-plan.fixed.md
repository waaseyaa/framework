- **Fixed — legacy rollback can no longer erase ledger truth for no-op or changed-source reverse methods (#2731):** `Migrator::rollback()` treated any override of `Migration::down()` as a supported reverse plan, so a shipped empty override (for example the OIDC token-schema migration) reported success, deleted the ledger row, left tables in place, and left strict verify green. A different class body under the same applied id could likewise reverse without matching the ledger checksum. Rollback now requires an explicit supported reverse (`Migration::providesSupportedReverse()` or `LegacyReversePlanCatalog`), binds the loaded source and package to the ledger identity (`[S1-DB113]`), preflights the whole last batch before the first `down()`, and refuses an ineffective reverse when the logical schema fingerprint is unchanged (`[S1-DB114]`). Missing-source refusal (`[S1-DB103]`), successful supported reverses, and V2's missing-legacy-source refusal are retained. Historical migration files are not edited; forward-only no-op overrides stay out of the catalogue.
