- **Changed — entity and blueprint introspection now converge on the registered
  field-type authority (#2786).** `FieldSchemaAuthority` emits closed,
  field-aware entity schemas; API and AI adapters consume it instead of owning
  structural type tables; unregistered field types fail closed; blueprint
  admission is derived from live plugin metadata; and AI schema generation now
  requires an explicit subject, access handler, and account so protected field
  metadata is not exposed by an unscoped catalogue. GraphQL explicitly encodes
  storage-decoded JSON values for its string adapter and
  preserves lossless decimals as strings instead of binary floats.
  Field registration now rejects declarations that the live plugin registry
  cannot project, and attribute-first entity admission defers explicit custom
  field ids to that same boot-scoped registry while retaining strict direct
  scalar inference. Unknown ids therefore fail closed with entity and field
  context, rather than relying on a static built-in roster.
  Entity, translation, revision, and SQL-column schema
  builders consume plugin-owned column shapes instead of parallel fallback
  maps. Internal-field visibility is shared across API and AI adapters;
  multi-value enum options are emitted and rendered through `items`; and the
  accepted Admin distribution carries the corrected widget behavior.
  A bounded compatibility window also retains dedicated non-blueprint plugins
  for the historical `int`, `bool`, `uri`, `timestamp`, `map`, and
  `list_string` ids. Their entity/API and GraphQL projections preserve the
  base release, including Unix-domain/text-storage/ISO-API timestamps and the
  path-specific URI column shape. The actionable hard removals are
  `computed`, `number`, `list_integer`, `list_float`, `password`, `double`,
  `datetime_immutable`, `slug`, and `array`; `uuid`, `bigint`, and `numeric`
  remain unregistered.
