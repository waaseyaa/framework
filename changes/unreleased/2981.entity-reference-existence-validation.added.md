- **Added — canonical `entity_reference` existence validation on the active
  repository save path (#2981).** When `EntityValidator` is configured and
  `save(..., validate: true)`, `EntityRepository` derives `EntityExists`
  constraints (via `EntityIdentifierResolver`) for declared `entity_reference`
  fields, refuses saves when the resolver is missing or target metadata is
  malformed, and kernel-built repositories always receive the resolver.
  `validate: false`, the `WAASEYAA_ENTITY_VALIDATION` boot opt-out, and types
  without `entity_reference` fields are unchanged. Manual per-type constraints
  still replace derived scalar checks per field; existence integrity composes
  afterward and cannot be removed. `on_delete` lifecycle and #2756
  polymorphic engagement targets remain out of scope. Non-Public reference
  values are exposed only to the canonical resolver-backed checker; arbitrary
  public `EntityExists` callbacks remain excluded from the closed reader.
