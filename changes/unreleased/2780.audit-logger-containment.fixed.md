- **Fixed — a broken audit logger could no longer escape the agent-tool or MCP `tools/call` paths (#2780):** `AuditedToolDispatcher::finalizeQuietly()` correctly caught a durable-ledger finalization failure after the delegated tool had already run, but the catch then called the injected logger unguarded — a `critical()` throw escaped `dispatch()` after the side effect had already committed, so a caller could receive an exception instead of the completed `ToolDispatchOutcome` and retry an action that already happened. `McpEndpoint::handleToolsCall()` carried the identical defect in its own post-execution finalize catch, and `tools/call` is dispatched directly from `McpEndpoint::handle()`, so nothing downstream caught for it: the throw reached the HTTP client as a transport failure for a write that had succeeded. The remaining post-decision audit-infrastructure reports in both classes had the same gap — each reports a refusal that is otherwise already final, so a logger throw there would replace an already-decided refusal with an unrelated crash: `agent_tool.audit_reservation_failed`, `agent_tool.audit_terminal_record_failed`, `mcp.audit_reservation_failed`, `mcp.audit_finalize_failed` (refusal path), `mcp.audit_terminal_record_failed`, `mcp.approval_store_unavailable` and `mcp.approval_consume_failed`. Every one of them now goes through a private `reportAuditFailure()` helper — one per class, deliberately not shared across the layer boundary between `waaseyaa/ai-tools` (L5) and `waaseyaa/mcp` (L6) — that wraps the logger call in `try`/`catch (\Throwable)` and swallows silently: a logging failure must never change a caller-visible outcome, and is deliberately not re-logged (no recursion into a broken sink; `error_log()` is reserved for the logging infrastructure itself).
