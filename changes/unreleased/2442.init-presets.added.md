- **Added — `site:init --preset=minimal|editorial` (#2442, ADR-024):** the governed `site:init` experience gains two deterministic, init-time-only presets between a plain, capability-declining site and a fuller one with governed visual authoring enabled. `minimal` activates only the `published_content` capability/recipe; `editorial` additionally activates the existing `governed_authoring` recipe, reaching a usable authenticated authoring starting point (draft, preview, revision history, restore, the shared Admin SPA/Anokii surface) without publishing any backend auth/security implementation code of its own. Both presets start from the same published skeleton and package cohort, and neither selects the `subscription` capability -- personal-data collection remains a separate, explicit decision. Per ADR-024 D-3/D-4 a preset is resolved once, by `SitePresetResolver`, into an ordinary `waaseyaa.site` answer document before the unchanged `SiteManifestParser` -> `SiteArtifactRendererFactory` -> `SiteInitializationService` pipeline runs; no preset name or runtime profile flag is ever persisted in `.waaseyaa/site.yaml` or `.waaseyaa/generated.json`, and no second transaction, execution, or ownership authority is introduced. `--preset` works both interactively (fewer product questions than the full wizard) and non-interactively (a small identity/content-type `--answers` seed document, rather than a complete manifest). Re-running with the same preset and seed is byte-identical and reports the exact proposed diff, through the existing dry-run/collision/journal machinery.
