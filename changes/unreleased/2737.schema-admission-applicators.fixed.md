- **Fixed — advertised `anyOf`/`oneOf`/`uniqueItems` constraints are now enforced before an agent tool runs (#2737):** `ToolInputSchemaValidator` — the single admission authority behind MCP `tools/call`, `AgentToolDispatcher`, `AuditedToolDispatcher` and `ContentSearchTool` — silently ignored the in-place applicators `allOf`/`anyOf`/`oneOf` and the `uniqueItems` keyword while its rationale claimed no first-party tool declared them. `ContentToolSet` does: nullable fields are advertised as `anyOf [<field>, {type: null}]`, reference-list items as `oneOf [integer >= 1, non-empty string]`, and list fields as `uniqueItems`. A `false` or over-long nullable string, a `0`/`""`/`false` reference item, a duplicate reference, or an over-`maxItems` nullable list therefore reached the handler and was refused only by publishing's domain validator (`execution_failed`), not by input validation. The validator now enforces `allOf`, `anyOf`, `oneOf` (exactly-one semantics, including the more-than-one-match case) and `uniqueItems` (strict decoded-JSON equality, like `enum`/`const`); when no alternative accepts a value and exactly one fits its type, that alternative's own violation is reported at its real path (`values.related.0`). Malformed union/duplicate input now yields `VALIDATION_FAILED` / `input_validation_refused` with zero handler calls, while valid nulls, strings, alternatives and partial payloads remain admitted; the same enforcement applies to advertised `outputSchema`s. `$ref` remains unimplemented, and the documented keyword subset is stated explicitly rather than claiming full draft 2020-12 conformance.
