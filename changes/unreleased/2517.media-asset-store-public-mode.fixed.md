- **Fixed — `MediaAssetStore::upload()` no longer publishes served media assets at tempnam's private 0600 mode (#2517 / FW-ARTIFACT-MODE-SCOPED-REPAIR-01 finding #6):** editorial image uploads are content-addressed under `uploadsDir` and resolved for HTTP delivery via `public://` and `MediaDownloadRouter`, so the on-disk bytes must be readable by the serving consumer (commonly a different user/process than the AI-tools upload call). The store already staged through `tempnam()` for fail-closed validation but `rename()`d into the final served path without an explicit `chmod`, leaving the asset at 0600. Publishing now `chmod`s the staging file to 0644 immediately before `rename()`, mirroring `ConfigManifestEnvelopeFile::write()`; content dedup skips remoding an existing file, and staging temps are still unlinked in `finally`.
