- **Fixed — preflight gates no longer misreport a stale local `vendor/` as a repository defect (#2926):** two gates read a stale checkout (`vendor/composer/installed.json` older than `composer.lock`, a locked package missing, a root `autoload-dev` PSR-4 mapping never re-dumped) as if the repository were wrong. `bin/check-delivery-agent-events` dereferenced `Opis\JsonSchema\Validator` unguarded, so a missing `opis/json-schema` was an uncaught PHP fatal (exit 255, stack trace). `tools/check-surface-parity.php` reported a declared FQCN the stale autoloader could not load as `orphaned: ... does not load`, whose repair text tells the contributor to add a CHANGELOG deprecation directive -- for `Waaseyaa\CLI\Io\StdinSource`, which exists at `packages/cli/tests/Io/StdinSource.php` under a declared root `autoload-dev` PSR-4 root, following that repair would have turned an environment fault into a real charter violation. A new dependency-free precondition, `bin/lib/vendor-freshness.php`, compares `composer.lock` (packages and packages-dev, by name, version, and source/dist reference) against `vendor/composer/installed.json` and the root `composer.json` PSR-4 map against `vendor/composer/autoload_psr4.php`; `bin/check-vendor-fresh` now delegates to it (gaining the version/reference comparison), and `bin/check-delivery-agent-events`, `tools/check-surface-parity.php`, `bin/generate-surface-map`, and `bin/check-pr-preflight` run it before touching the autoloader, exiting with the distinct `VENDOR_FRESHNESS_EXIT_CODE` (3) and one actionable `vendor/ is stale relative to composer.lock -- run composer install` message. The delivery-ledger gate additionally refuses with the same code when the validator class is unloadable even though the metadata agrees. `SurfaceDeclarations::validate()` now distinguishes a real orphan (no file on disk defines the symbol) from an `environment:` fault (a file under a declared package or root PSR-4 root -- `autoload` or `autoload-dev` -- defines it but the autoloader cannot load it), and both surface scripts route the latter to the precondition exit code instead of the §4 validation failure. `bin/check-pr-preflight` checks once up front and runs no gate against a stale checkout. Proofs: `tests/Architecture/VendorFreshnessPreconditionTest.php` and `tests/Architecture/SurfaceDeclarationEnvironmentFaultTest.php` build deliberately stale vendor fixtures and an on-disk-but-unloadable declaration fixture; `tests/Integration/Policy/CheckVendorFreshTest.php` gains version and reference mismatch cases.
