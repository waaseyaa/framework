- **Fixed — blueprint governance emitters: policy discovery, check-expect vocabulary, and four compile-time refusals (#2788, FW-SITE-BLUEPRINT-01E review round 1):** `AccessPolicyEmitter` now emits `#[Waaseyaa\Access\Gate\PolicyAttribute(entityType: ...)]` on every generated `<Entity>Policy` class — a generated policy with no attribute was never discovered by `PackageManifestCompiler`'s scan, so `AccessPolicyRegistry` never wired it into `EntityAccessHandler` and every declared grant was silently dead. `GovernanceCheckEmitter::expectAllowed()` now maps the correct per-kind vocabulary (`granted` for `role_permission`, `allowed` for `workflow_transition`, `allow` for `entity_access`) instead of a `stripos($expect, 'grant') === 0` prefix match that compiled every `allow`/`allowed` check as a DENY assertion. `EntityClassEmitter` now refuses `GEN007_UNSUPPORTED_DECLARATION` when a workflow-bound entity (or one of its relationships) declares its own `status` or `workflow_state` field — the former was silently overwritten by every granted `TransitionService` transition, the latter produced an unparseable duplicate-property class. `GovernanceCheckEmitter` now refuses `GEN007_UNSUPPORTED_DECLARATION` when a `workflow_transition` check targets a workflow with zero declared bindings (previously an uncoded `AssertionError`/`TypeError`), and refuses `GEN006_MALICIOUS_IDENTIFIER` when two checks of the same kind PascalCase to the same generated test method name (previously an unparseable duplicate method). `WorkflowDefinitionEmitter` similarly refuses `GEN006_MALICIOUS_IDENTIFIER` for two colliding workflow ids, and no longer emits an empty `config/sync/workflows.assignments.yml` when a blueprint declares workflows with zero bindings. `GovernanceDefaultDenyTest` now also asserts the three companion invariants decision (i) always intended: no emitted role is ever `administrator`, every permission a role/transition/policy references is a declared `ApplicationBlueprintPermissions` constant, and every entity with a declared policy has a reflectable `#[PolicyAttribute]` class. `PermissionCatalogueEmitter`'s generated `seed()` now carries the permission's title as its `description` rather than an empty string. The `complete.yaml` fixture's `article.status` enum field is renamed to `article.stage` (it collided with the newly-refused workflow field) and gains two `entity_access`/`workflow_transition` checks using the previously-mismapped `allow`/`allowed` vocabulary, exercised end-to-end via the existing `proc_open` PHPUnit proof.
