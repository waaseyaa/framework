- **Fixed — the preflight gate scanners no longer walk nested worktrees or nested `vendor/` trees (#2925):** `bin/check-s1-sqlite-contract`, `bin/check-s1-schema-authority` (through the shared `bin/lib/s1-roster.php` scanner, which `check-s1-configuration-activation` and `check-s1-configuration-authority` also use) and `bin/check-access-hardening` enumerated files with a `RecursiveDirectoryIterator` over the filesystem, so in a developer clone they descended into trees hosted CI never has: registered nested git worktrees under `.worktrees/` or `.claude/worktrees/` and a populated `packages/<pkg>/vendor/`. On one primary checkout that produced 24,780 phantom findings across the three gates (18,844 + 5,932 + 4 — the access-hardening four being `AH004` hits inside a vendored copy of `waaseyaa/foundation`), and the documented repair for the SQLite gate, `--write-construction-roster`, would have committed `.worktrees/...` paths into the tracked roster. #2865 and #2866 had treated this class of bug by extending `s1RosterIsExcluded()`, a hand-maintained path denylist that re-created the ignore boundary by hand — and missed `.worktrees/` outright, while `check-access-hardening` had no exclusion at all beyond requiring `/src/` in the path.

  The scanners now derive their file list from git. A new shared helper, `bin/lib/repository-files.php` (`repositoryFiles()`), runs `git ls-files -z --cached --others --exclude-standard` scoped to each scan root, so a scan sees tracked files plus untracked files git would add — the worktree-inclusive semantics `docs/specs/governed-gates.md` §1 requires — and nothing else: `.gitignore` is the exclusion by construction, git never descends into another repository's work tree, and there is no denylist left to fall out of date (`s1RosterIsExcluded()` is removed). A root git cannot enumerate fails closed with a clear error instead of falling back to a filesystem walk, and because roster writing composes the scan, `--write-*-roster` can no longer emit a non-repository path. Every git child the gates run drops git's repository-selecting environment (`GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, `GIT_COMMON_DIR`, ...): a pre-push hook run from a linked worktree exports `GIT_DIR=<main>/.git/worktrees/<name>`, under which `ls-files` would have enumerated the hook's repository instead of the scan root and the access-hardening self-test's fixture `git init` would have reinitialised the developer's own gitdir as bare. Unanchored `node_modules/` and `tmp/` join the root `.gitignore` so the ignore boundary covers every build tree the removed denylist did. `S1RosterLibraryTest` now builds a real git fixture — a tracked candidate, an untracked candidate, two registered nested worktrees, a nested `packages/demo/vendor/`, ignored build dirs and an unignored nested repository, each seeded with matches — and asserts only the repository candidates are found; the new `tests/Architecture/AccessHardeningGateTest.php` does the same for the access-hardening gate, including the exact `packages/ai-agent/vendor/waaseyaa/foundation/...` production shape and a negative control proving an untracked source file is still scanned. No roster regeneration was required: regenerating all four `support/s1-*-roster.json` files with the new scanner yields a zero diff, and all three gates pass read-only against a checkout holding sixteen nested worktrees and a populated `packages/ai-agent/vendor/`.
