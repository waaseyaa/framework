- **Fixed — a broken logger could crash an MCP request and suppress its terminal audit record (#2886):** six `logger?->error(...)` sites in `McpEndpoint` — the rate-limiter durability check, `protocolExecute()`'s handler-threw and malformed-response branches, `resourceProtocolExecute()`'s same two branches, and `executeResourceRead()`'s handler-threw branch — called the injected logger directly. Four of the six report *before* their own `auditTerminal()` call, so a logger that throws there both crashed the request as an uncontrolled 500 and prevented the terminal audit record from ever being written, a strictly worse outcome than the `critical()`-family gap #2780 fixed (which always reports after the outcome is already durable or decided). All six now route through a new private `reportOperationalFailure()` helper — the same try/catch-and-swallow shape as `reportAuditFailure()`, at `error` rather than `critical`, since this family has no committed side effect behind it. `packages/mcp/tests/Unit/McpEndpointAuditLoggerContainmentTest.php` drives every site with a throwing logger, asserting the request still completes and, for the four that precede it, that the terminal record was still written.
