- **Fixed — auth UI scaffold manifest was written at a private mode, outside the portable-artifact contract (#3061):** `scaffold:auth` wrote `.waaseyaa/scaffold-manifest.json` via `tempnam()`, which always creates its temp file at mode 0600 regardless of umask, then `rename()`d it into place without ever chmod-ing it — leaving the published ownership/provenance manifest at 0600 instead of the {0644, 0755} portable-artifact contract every other generated project file carries. The manifest is meant to be committed alongside the generated auth UI files it tracks (analogous to `.waaseyaa/bimaaji-install.json`), so a 0600 mode left it unreadable to other processes/users that consume the bundled tree. `AuthUiScaffoldManager::writeManifest()` now `chmod($temporary, 0o644)` before the publishing `rename()`, mirroring the existing correct pattern in `ConfigManifestEnvelopeFile::write()`.

  Confirmed by empirical reproduction on the real `publish()`/`acceptCurrent()` production paths (pre-fix inode mode 0600). New behavioural tests in `packages/cli/tests/Unit/Scaffold/AuthUiScaffoldManifestModeTest.php` materialize the manifest through those real paths and assert on-disk inode modes plus manifest integrity, with an explicit discriminator that fails if tempnam()'s 0600 default returns. Bounded to `packages/cli/src/Scaffold/AuthUiScaffoldManager.php` and its tests; see `docs/change-records/FW-ARTIFACT-MODE-SCOPED-REPAIR-01.md` finding #4.
