- **Added — `waaseyaa.site-seed` v1, a closed and versioned seed document (#2442):** `site:init --preset --answers` takes a small identity/content-type seed rather than a complete manifest, and that seed is now a governed input contract of its own instead of an open bag of keys. `Waaseyaa\SiteContract\Seed\SiteSeedParser` requires `schema: waaseyaa.site-seed` and `version: 1` and rejects every unknown top-level or nested key, duplicate mapping key, duplicate content-type identity or canonical route, and ill-typed value — reporting the failure at its original JSON Pointer with the same `SITE0xx` codes `SiteManifestParser` uses. Previously an unrecognized key (a typo, or an operator-supplied capability decision the resolver did not read) was silently discarded while `site:init` reported success. This is not a second validation authority: the seed parser reuses the existing `ManifestShapeReader` closed-shape readers, and the application-identity and content-type sections are now read by one shared implementation for both documents.
