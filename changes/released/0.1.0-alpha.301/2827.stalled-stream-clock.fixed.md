- **The `AnthropicProviderTransportTest` stalled-stream timeout contract is now
  deterministic under full-suite load (#2827).** The test's wall-clock lower
  bound measured elapsed time with `microtime(true)` (`CLOCK_REALTIME`), which
  on a WSL2 / Hyper-V guest is periodically stepped backward by the host's
  time-sync correction; a genuine 3s hold to the total timeout could measure as
  an early return and fail
  `withoutALowSpeedGuardAStalledStreamHoldsTheWorkerForTheWholeTotal`, exactly
  as reproduced in the reported full-Unit-suite failure. `timeFailure()` now
  measures with `hrtime(true)` (`CLOCK_MONOTONIC`), which a wall-clock step
  cannot move, restoring the original 2.5s floor as a trustworthy signal. The
  test also ports the cURL reason-classification coverage from the sibling
  `OpenAiCompatibleProviderTransportTest` fix (#2716 / #2795,
  `assertPeerEndsOnlyOnTheTotalTimeout()`): a raw probe issued with the exact
  timeout options the provider installs proves the total bound — not an
  unrelated early teardown — is what ends the stalled stream, independent of
  the wall-clock floor. Test-only; no production code changed.
