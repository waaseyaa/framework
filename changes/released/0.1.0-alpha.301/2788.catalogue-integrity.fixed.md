- **Fixed — permission/role catalogue integrity (#2788, FW-SITE-BLUEPRINT-01E independent review):** `PackageManifestCompiler` now refuses to compile when a permission id is declared by two installed packages or by the root application and an installed package (`PermissionManifestCollisionException`, naming both sources in installed order) instead of letting the later entry silently overwrite the earlier owner; a cache reload still re-merges the root application's own entries idempotently. `AbstractKernel::boot()` now composes the permission catalogue and the validated role repository BEFORE any provider boot hook runs, so an invalid catalogue or an uncatalogued role grant refuses boot before a provider can perform a durable write (the generated governance provider seeds workflows in `boot()`). The kernel retains the exact validated `RoleRepository`, exposes it as `roleRepository()`, and binds that same instance in the handler container — providers' `roles()` is consulted exactly once. `PermissionHandler::fromProviders()` rejects malformed shapes with a deterministic owner-naming `LogicException` rather than a PHP warning or `TypeError`: a non-array definition, a missing, non-string or empty `title`, a non-string `description`, an unknown member, or an invalid id (empty, padded, containing a control character, or a non-string key), for manifest and provider entries alike, while duplicate ids are still reported first.
