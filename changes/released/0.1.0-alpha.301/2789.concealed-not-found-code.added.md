- JSON:API single reads now carry the stable machine-readable code `ENTITY_NOT_FOUND` on their 404, so a client can branch on that boundary without parsing prose. The non-oracle contract is unchanged: the code is emitted from the one shared not-found document rather than from a branch on the denial, so for the same type and id a missing entity and a view-denied entity still return byte-identical status, title, code, detail and full document. Every other 404 keeps its existing codeless shape — the unknown entity type, the translation 404s, and the `PATCH`/`DELETE` 404s, which answer a denial with a plain 403 rather than concealing it.
