- **Fixed — vendor freshness now refuses first-party autoload maps bound to another checkout (#2972):** the existing dependency-free precondition still checks missing and mismatched locked packages and declared PSR-4 namespaces, and now also checks candidate-owned root/path-package paths across Composer's compatibility and runtime-static PSR-4, optimized classmap, and autoload-files maps. Ownership comes from manifests rather than package-name prefixes; generated descendant prefixes cannot shadow an owned parent unless a nearer third-party declaration owns them; canonical candidate-internal symlinks and Composer-valid missing PSR-4 leaves under candidate ancestors pass; donor or dangling symlink ancestors and symlink-plus-parent traversal escapes fail; external third-party mappings remain distinct; and a lexically candidate-owned path package or generated first-party path resolving to a donor fails before an expensive gate with the observed path and candidate-local repair. Composer's optional compatibility files map is required only when an owned declaration or runtime map has files. The guard reads generated declarations without invoking the application autoloader, never regenerates vendor, and tells an operator to unlink only a candidate `vendor` or nested metadata symlink before installing.
