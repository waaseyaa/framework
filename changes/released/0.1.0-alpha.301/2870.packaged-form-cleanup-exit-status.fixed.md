- **Fixed — `tests/PackagedForm/check-*` and `tests/ReferenceConsumer/check-reference-consumer` teardown can no longer overwrite a passed proof's exit status (#2870):** each of the twelve `check-*` scripts under `tests/PackagedForm/`, plus the required `site-reference-consumer` CI job's `tests/ReferenceConsumer/check-reference-consumer`, installed `trap cleanup EXIT` with a bare `rm -rf -- "$work"` (`"$work_root"` in the reference-consumer script); under `set -euo pipefail` a cleanup-time removal failure (a lingering process, a filesystem race against something the proof itself just created) is itself an error, and that error's exit status silently became the *script's* exit status, overwriting a proof that had already fully passed. The reference-consumer script is the most exposed instance of the shape: its cleanup fires after a `git init` against the same work directory. `cleanup()` now guards the removal with `rm -rf -- "$work" || echo "warning: failed to remove $work" >&2` in every affected script, carrying an inline comment stating the invariant, so a failed teardown is reported on stderr instead of corrupting the result — while an explicit failure path elsewhere in the script (e.g. `exit 1`) still propagates unchanged. `check-consumer-key-hygiene` has no such trap and was left alone. `tests/Architecture/PackagedFormCleanupExitStatusTest.php` locks the shape going forward across both directories: it rosters every script carrying `trap cleanup EXIT` (a new one not on either roster fails the test), asserts each rostered cleanup neutralizes its exit status while still reporting a leak, and carries a runnable negative control that executes the exact pre-fix shape against a work directory whose removal genuinely fails, proving it really does corrupt a successful exit. A repo-wide survey (`rg -l 'trap cleanup EXIT' --glob '!vendor'`) found the identical bare-`rm` shape in seven more scripts outside these two directories (`bin/test-isolated-package`, `bin/promote-exact-source-artifact`, `bin/build-admin-dist`, `bin/build-exact-source-artifact`, `bin/materialize-exact-source-artifact`, `tools/optional-domain-install-shapes.sh`, `scripts/acceptance-frankenphp-worker.sh`); those are deliberately left out of scope of this fix and tracked for a follow-up — see the PR description for the full accounting.
