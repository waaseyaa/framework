- **Fixed — `StreamHttpClient` no longer returns a truncated body as HTTP success (#2708):** `fetch()` used `stream_get_contents()` with a byte ceiling and treated the prefix as a complete response, so an over-limit or short `Content-Length` body could surface as HTTP 200. The client now enforces declared length and the byte ceiling, throwing `HttpRequestException` with `$response === null` — over the ceiling, mismatched `Content-Length`, EOF before the declared length, and mid-body timeout all fail closed. A body whose size equals the configured maximum still succeeds, including chunked and connection-close responses. New diagnostic messages do not embed response bytes, `Authorization`, or the URL.
