- **Added — a frozen CI measurement baseline, collected once and classified offline (#3087, Task 4; measurement owner #2869):** `bin/collect-ci-run-evidence` resolves the hand-frozen cohort spec `tools/ci-measurement/cohort-2026-09.json` into `tools/ci-measurement/dataset-2026-09.json` in one read-only GitHub pass; `bin/classify-ci-run-evidence` labels every job (root execution / setup-or-infrastructure / derivative aggregate / expected conditional skip / unexpected skip-or-missing-prerequisite / cancellation / publication-only / success) and every run attempt (first-pass outcome, rerun and flake outcome under a stated head-SHA rule, critical path by actual timestamps, PR latency, cost proxy) offline; and `bin/report-ci-measurement` renders `docs/audits/ci-measurement-baseline-2026-09.md` deterministically — two renders of one dataset are byte-identical. Comparability is **job structure, not workflow bytes**: each run's workflow file is fetched at its own head SHA, composed by the Task 2 generator `bin/generate-ci-workflow-inventory`, and reduced to a SHA-256 over every job's key, expansion, literal matrix axes, sorted `needs`, aggregate gate token and visible contexts, so a reformat or a comment keeps a run in the cohort and a renamed job, a wider matrix or a new dependency edge takes it out. Every dataset field is typed `observed` or `derived` per `docs/specs/delivery-telemetry.md`, and nothing is derived from a value not observed in the same dataset — the random-order log parse and the shard JUnit parse each carry an `observed` fetch record (id, byte length, SHA-256, fetched at) beside their `derived` identities. **Billed runner minutes are structurally unavailable** on a public repository (`/actions/runs/{id}/timing` reports `duration_ms: 0`, and organization billing needs an `admin:org` scope), so summed job-wall seconds weighted by GitHub's published per-OS multipliers is recorded and reported as a **cost proxy**, never as spend. The baseline is evidence only: it makes no cadence or shard-width recommendation (that is Task 8), changes no workflow, ruleset, branch rule, product code, release or deployment behaviour, and writes nothing to GitHub.
