# FW-2734 — outermost transaction completion

Status: implementation candidate

## Intent

Make entity mutation tokens and POST/AFTER lifecycle notifications reflect the
outermost database outcome. A repository mutation nested in another managed
transaction must not publish those effects when its savepoint is released; it
must publish them exactly once after the outermost commit and discard them on
any rollback that removes the mutation.

## Decision

- `DatabaseInterface` remains unchanged. Transaction implementations that can
  preserve outermost-completion semantics implement a new optional
  `TransactionCompletionInterface` alongside `TransactionInterface`.
- `DBALDatabase` owns one completion coordinator per Doctrine `Connection`,
  shared by every wrapper around that connection. Each managed transaction
  opens a coordinator frame. A nested commit merges callbacks into its parent;
  only the physical outer commit drains them. A rollback discards the affected
  frame.
- `UnitOfWork` requires the returned transaction to expose this completion
  contract before it executes mutation work. It registers one completion
  callback containing its successor-token callbacks and buffered events.
- A transaction opened directly through Doctrine's raw `Connection` is not a
  managed parent and cannot be observed safely. Starting a framework-managed
  transaction beneath it fails before any mutation. First-party scheduler
  callers migrate from `Connection::transactional()` to the managed
  `DBALDatabase` boundary.
- A failing post-commit callback or event is logged with bounded event metadata;
  later callbacks and events still run. Collected failures surface only after
  the complete drain as committed completion failures, never as fictional
  database rollbacks.
- First-party outer boundaries that can contain repository work use the managed
  helper. Multi-step publishing commands reload their transaction-visible
  snapshot between mutation claims instead of depending on an uncommitted
  successor token being installed into the caller's object.

## Work packages

1. Pin separate-owner nesting, commit/rollback, unmanaged-parent refusal, and
   listener-failure continuation with retained-red tests.
2. Add the transaction-completion contract and DBAL per-connection coordinator.
3. Route `UnitOfWork` completion through that contract and pass repository
   logging into every unit of work.
4. Move shipped raw scheduler and schema-coordination outer transactions to the
   managed boundary, and remove multi-step publishing's dependency on early
   in-memory successor-token installation.
5. Cover the real fence/repository composition on both SQL storage layouts.
6. Update the entity, infrastructure, and concurrency contracts; add the
   governed changelog fragment and exact-head verification evidence.

## Compatibility

- `DatabaseInterface` and `TransactionInterface` method sets do not change.
- Database decorators that pass through `transaction()` automatically preserve
  the concrete completion-aware transaction object.
- A custom transaction implementation used by `UnitOfWork` must implement the
  new completion interface. Failing before mutation is intentional when the
  implementation cannot prove outermost completion.
- Direct Doctrine transactions remain available for migration-only escape-hatch
  work, but they may not enclose repository mutations.
- Same-`UnitOfWork` re-entry retains its existing single-frame behavior.

## Exclusions

This change does not provide cross-database atomicity, transactional external
effects, queue settlement, or token-spending semantics. Issue #2775 remains a
dependent change and starts only after this contract lands. The separate
PRE_DELETE refusal policy in #2733 is not modified here.

## Required evidence

- separate `UnitOfWork` instances under outer commit and rollback;
- save, delete, saveMany, and deleteMany through the scheduler fence on
  `sql-blob` and `sql-column`;
- held-object token state after outer rollback;
- revision-pointer returned-token and notification state across outer rollback
  and commit;
- one throwing listener cannot starve later events or another repository;
- unmanaged raw Doctrine nesting fails before mutation;
- focused Unit/Integration/Architecture suites, full preflight, and changed-line
  coverage bound to the exact candidate.
