## Defect and outcome

`DbalQueue::dispatch()` accepts any object. The provider-built persistent worker
has `JobHandler` by default, so an accepted `GenericMessage` has no supporting
handler. `Worker::handleMessage()` currently falls through, after which
`processJob()` acknowledges the delivery as if a void handler had completed.
The durable row disappears without handler execution or a failed-job record.

The worker must instead produce a typed `UnhandledQueueMessage` failure. That
failure follows the existing bounded worker policy: release with the existing
backoff while attempts remain, then record the signed payload and typed error in
the failed-job repository before rejecting the delivery. The error names only
the message class, not message fields or serialized payload bytes.

## Decisions

- **D1 — keep the object dispatch contract.** `QueueInterface` and `DbalQueue`
  continue to accept non-`Job` objects. This repair does not narrow a public
  contract merely because the provider's default roster handles only `Job`.
- **D2 — no implicit success.** Exhausting the worker handler roster throws
  `Waaseyaa\Queue\Exception\UnhandledQueueMessage`. A matched handler that
  returns `void` remains successful and is acknowledged.
- **D3 — bounded retry and dead-letter.** No-handler failures use the existing
  `Job::$tries` or `WorkerOptions::$maxTries`, existing exponential backoff, and
  existing failed-job recording path. The default non-`Job` budget is three
  attempts. No unconditional catch-all handler or infinite retry is introduced.
- **D4 — preserve disposition ordering.** A failed row is persisted before the
  transport delivery is rejected. If failed-row persistence throws, rejection
  is not attempted, preserving the reserved queue row for visibility-timeout
  recovery. Authority scope closes before release, failed-row persistence, or
  rejection. Deliberate duplicate-occurrence acknowledgements remain outside
  handler resolution.
- **D5 — preserve adapter semantics.** `Worker` still invokes only the first
  supporting handler. `SyncQueue` still invokes every supporting handler and
  continues to permit no-handler inline dispatch. `MessageBusQueue` is
  unchanged.

## Discriminating proof

The regression test must apply the shipped `CreateQueueTables` migration and
resolve `QueueInterface`, `Worker`, `DbalTransport`, and
`DatabaseFailedJobRepository` through the real database `QueueServiceProvider`.
It supplies a real `ApplicationSecret`, `SystemQueueEnvelopeFactory`,
`ScopedQueueAuthorityRuntime`, and `StableRuntimeEpoch`.

With `maxTries: 2`, an unsupported `GenericMessage` must be released after the
first attempt and durably failed after the second. The failed row must pin the
typed class and operator-visible message; a subsequent pop must report no
pending delivery. In the same composition, a custom `GenericMessage` handler
must execute exactly once and acknowledge normally. Existing matched `Job`,
first-match, duplicate occurrence, authority cleanup, and failed-store outage
controls remain green.
