# FW-GENERATION-UNITS-08 — controlled apply and command activation

Date: 2026-09-04. Forge mirror: #2846. Authority: ADR-025 D-6, D-7, D-12 and D-14.

## Scope and accepted decisions

Activate the existing generation authority for site:init and unit-aware site:doctor. Public apply consumes the immutable transported ArtifactPlan and reviewed plan/state digests; it never recompiles. Other make/scaffold migrations and seeded compiler admission remain closed. GeneratedSite and renderer output contracts stay unchanged. No new storage or publication authority is introduced.

The maintainer accepted two architecture clarifications: preserve the closed apply-request format and permit location-free GEN005 when no changed location is independently provable; give recovery its own site.recover operation identity based on deterministic validated recovery instructions rather than inventing an unavailable original publication digest. ADR-025 records both. Existing journal recovery derives its instructions from that journal; existing reserved control-residue cleanup derives a sorted closed list from the same existing residue policy, without new names or deletion authority.

## Execution and transport

Default initialization compiles once, prechecks deterministic collisions, takes the existing lock, recovers, evaluates and confirms, then enters the same private gate as public apply. Creating the lock does not pre-write a planned artifact. The control-ignore file is journalled; cancellation and successful rollback leave no fresh control-ignore artifact. Successful default stdout/counts and artifact bytes remain compatible. Structured actual changed paths include every published effect, while status remains plan-artifact-only; the DTO's unsupported changed-subset-of-status restriction is removed without changing its wire shape.

State observation uses the existing reader and target capture. Raw metadata and Composer identities bind the bytes actually interpreted, not a later rehash. Apply checks before preparation, checks the prepared observation, and checks current state before publication. Existing publisher observation and prior-tuple checks protect staged and installed effects and unchanged reviewed targets at the guarded boundaries. This is protection at those checked boundaries, not an OS-level atomicity claim against arbitrary noncooperating writers.

The CLI adds opt-in --json for evaluation, result and ordered receipts. Default text and exit codes remain; JSON publication requires --yes. Preview/cancellation emit no apply receipt. A successful recovery followed by publication emits correlated recovered and applied receipts; cleanup-only recovery emits its recovery outcome. Failed publication retains its error/nonzero exit even after successful rollback. Invocation carriers and receipt-bearing exceptions return evidence without a mutable last-result cache or receipt sink.
