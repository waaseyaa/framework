## Security boundary and deliberate migration

Alert #291 [GHSA-c8p4-j97h-3vg8](https://github.com/advisories/GHSA-c8p4-j97h-3vg8)
is fixed at 21.0.0; #276
[GHSA-834v-8h66-3h79](https://github.com/advisories/GHSA-834v-8h66-3h79)
requires 21.0.4. Fresh structured advisory ranges and published
[21.0.4 metadata](https://registry.npmjs.org/happy-dom/21.0.4) are authority;
older advisory prose saying no patch is stale.

[21.0 migration notes](https://github.com/capricorn86/happy-dom/releases/tag/v21.0.0)
disable stylesheet and iframe loading by default and introduce opt-in settings.
[21.0.4 notes](https://github.com/capricorn86/happy-dom/releases/tag/v21.0.4)
fix module alias injection and opaque-origin iframe isolation. This candidate
retains the new safe defaults; no resource or evaluation opt-in is added to
repository configuration. Nuxt test-utils 4.1.0 peers allow Happy DOM >=20.0.11;
Vitest's optional peer is unrestricted. Peer support is not qualification.

Actual Nuxt/Vitest baseline loads Happy DOM without custom settings. A new
loopback regression fails on the old installed package because iframe and
stylesheet markup issue two HTTP requests; normal DOM clicks and a direct
loopback-server control succeed. This establishes test-environment reachability,
not a public application route accepting attacker input.

JavaScript evaluation defaults off. An isolated helper explicitly opts in for
the compiler check only: two invalid import aliases execute harmless synthetic
window markers on the base, alongside a legitimate JSON import. No host-process,
filesystem-access or external-network exploit is executed. The helper separately
checks default passive resources, normal DOM behavior and deliberate local-only
resource-loading control. No production targets or sensitive data.
