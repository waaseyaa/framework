# Framework host-portable preflight gates

Status: implementation candidate for Framework #3096 (child of #2679, program
#2676). Source: `FW-CI-CHECK-ROSTER-AUDIT-01.md` "Deferred observations".

## Problem

On native Windows, `php bin/check-pr-preflight` failed five gates on every run
regardless of the change under test, so an installed pre-push hook blocked
every push. None was a repository finding:

| Gate | Mechanism |
|---|---|
| `check-package-layers-pl008-self-test` | Child gate started from a POSIX `VAR=value php … 2>/dev/null` shell string, which `cmd.exe` cannot run, so every "must fire" step read as a detection failure. It was not a fixture-permission problem. |
| `check-admin-coercion-patterns` | Git for Windows `grep` rejects `-P` in its default locale (exit 2). The pattern is pure ERE. The self-test also counted that scan error as a detection, a false pass. |
| `check-delivery-agent-events`, `check-covers-nothing-companions` | `proc_open` of the extensionless Bash `bin/git`, which CreateProcess cannot start. |
| `check-ingestion-defaults` | MSYS `/c/…` paths interpolated into Python source reached a native Windows Python. |

`PreflightParityTest`'s synthetic manifest used POSIX `true` / `echo broken;
false`. Under `cmd.exe` the always-red gate reported `ok`, a false green. The
runner's own `git config waaseyaa.driftBase` lookup used `2>/dev/null` and was
silently ignored on Windows.

## Contract

`docs/specs/governed-gates.md` §8: child processes start from argument arrays;
PHP gates start Git through `bin/lib/repository-git.php` (the `bin/git`
adapter on POSIX, the Windows Git executable on native Windows, per
`docs/governance/agent-contract.md`); Bash gates use only what Git for Windows
Bash provides; self-tests count only a genuine detection. Every gate runs
genuinely on Windows, so no `not-run-here` outcome was introduced. Linux gate
commands, messages and exit codes are unchanged. The one intended Linux-visible
change is that the admin coercion self-test now fails on a scan error instead
of passing.

## Verification boundary

Focused regression tests fail on native Windows before the change and pass
after. They exercise real behaviour and negative controls on Linux. The
native-host classification in `docs/specs/native-host-support.md` is unchanged:
a local Windows pass is not a support claim until a native Windows CI job runs
these entrypoints (#2678). Linux and hosted CI qualification of the exact
candidate is still required.
