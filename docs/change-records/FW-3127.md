# Framework deployer user schema transition

Status: implementation candidate for Framework #3127, scoped from #2548 and
#2549.

## Problem

Artifact preparation rejected a serving database whose `user` table still had
the six-column legacy shape when the artifact carried the current canonical
identity columns. The generic `INSERT OR REPLACE` identity merge also allowed a
primary-key collision to discard an unrelated identity or silently accept a
uid/uuid remap.

## Contract

The runtime catalogue declares the only permitted user schema evolution: the
artifact may add nullable TEXT-affinity `identity_name_key` and
`identity_mail_key` columns with the named unique, non-partial indexes. All
pre-existing columns must be exactly the legacy roster (`uid`, `uuid`,
`bundle`, `name`, `langcode`, `_data`) and all constraints remain exact;
reverse or undeclared drift fails closed. User merges bind identities by stable `uuid`, reject both
uid-to-new-uuid and uuid-to-new-uid remaps, replace only a row whose uid and
uuid both match, and use a plain insert for serving rows so unrelated unique
collisions abort atomically. Existing exact-schema IdentityMerge tables retain
their established destination-wins behavior.

## Verification boundary

Focused deployer unit tests cover the legacy-to-current transition, serving
credential and reference preservation, artifact-only canonical keys, reverse
and undeclared schema drift, malformed identity additions and indexes, both
identity remaps, canonical-key collision rollback, integrity, foreign-key
checks, and byte-identical inputs.
