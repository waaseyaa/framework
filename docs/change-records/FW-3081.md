# Split-artifact symlink negative control on native Windows

Status: implementation candidate for Framework #3081 (under #2679, program
#2676). Observed while qualifying #3074.

## Problem

`tests/PackagedForm/check-split-artifact-acceptance` re-runs every acceptance
assertion against sixteen seeded corruptions and fails if any survives. On
native Windows without the symlink privilege, `source-symlink-installed` could
not plant its corruption. The control ignored `symlink()`'s `false` return, so
`assert_no_source_symlinks()` inspected a tree with no link, passed, and the
harness refused the run with `undetected: source-symlink-installed`. The other
15 controls and every surface passed. The refusal was safe, but it described a
host limit as a harness defect. It also left no way to record an honest local
result.

## Contract

A control the host cannot construct is `not-run-here`
(`docs/specs/governed-gates.md` §8):

- The control checks that the link exists (`symlink()` succeeded and
  `is_link()` holds). If not, it raises `NegativeControlNotRunHere`, which is
  deliberately not an `AcceptanceFailure`. It is never counted as caught.
- Any undetected control still fails the run with exit 1, whatever else was
  not run here.
- On native Windows (`PHP_OS_FAMILY === 'Windows'`), a not-run-here control
  makes the run INCOMPLETE: exit 3, with the controls named, and never the
  pass line.
- On every other host, a not-run-here control fails closed with exit 1. Hosted
  Linux `ci/split-artifact-acceptance` is the evidence owner for the symlink
  refusal and must execute it.

The other 15 control closures, the composition, exported-files, bootstrap and
`--no-dev` surfaces, and the wrapper's commands are unchanged. The
`negative-control-verdict` subcommand drives the same verdict with synthetic
controls, and optionally the real symlink control against a throwaway project,
so `tests/Architecture/SplitArtifactAcceptanceGateTest.php` proves it on every
host in seconds. It never inspects a consumer, so it cannot stand in for
`self-test`.

## Verification boundary

The new fast-half cases fail against the base engine and pass after the change
on native Windows and on Linux (WSL2). On Linux the real control is caught by
the installed-source refusal. On native Windows the full harness now ends
INCOMPLETE rather than refused, with 15 controls caught. A local Windows run is
not acceptance evidence: hosted Linux CI qualification of the exact candidate
is still required, and it must show `source-symlink-installed` caught.
