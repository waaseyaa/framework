# Issue 2344 implementation plan

This plan implements `docs/specs/page-builder.md` in retained-red slices. Each
work package is independently reviewable and keeps the shared model below both
editor clients.

## Sequence

1. WP01 begins with failing unit tests for the document envelope, canonical
   codec, exact-version registry, duplicate refusal, and validator violations.
2. Add the Layer 3 `waaseyaa/page-builder` package and make only those tests
   pass. Run package, composer-policy, package-layer, and PHPStan gates.
3. WP02 adds failing command tests for stable-ID targeting, moves, duplicate,
   remove, invalid destination, and stale fingerprint. Implement commands as
   pure transformations.
4. WP03 adds the entity application-service contract and tests that every
   persistence path carries the observed entity concurrency token and creates
   one revision. Do not weaken the wider DB-03 contract to make this pass.
5. WP04 exposes one authenticated server contract through admin-surface and
   binds exact-revision preview through publishing grants.
6. WP05 and WP06 implement Admin SPA and Anokii clients against shared fixtures
   and wire types. Neither client gets a private persistence path.
7. WP07 composes ListingDefinition references and structured content workflows.
8. WP08 runs browser and accessibility acceptance locally against exact
   framework, Anokii, and Sheguiandah candidates.
9. WP09 updates exact downstream dependencies, regenerates Stage 1, and deploys
   only to separately authorized staging after local acceptance is green.

## Review gates

- One traceable commit/PR per work package with `Part of #2344`.
- A changelog entry in every code work package.
- `spec-reviewed:` trailer after explicit spec review.
- Package-local tests first, then Unit/Integration/Architecture suites and all
  repository verification gates proportional to the touched surface.
- Independent review after WP03, WP06, and WP08 when a permitted reviewer is
  available. Claude use, if requested, must use Opus 5 or Sonnet 5, never Fable.
- No release, production mutation, DNS change, production recovery exercise,
  or WordPress cutover is authorized by this plan.
