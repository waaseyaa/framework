# ROUTE-METADATA-01 explicit execution boundary

Base: `5bfc3daf640ce576690b91cb2a2c0dbf0a5da628`. Owned checkout: `framework-worktrees/bimaaji-route-wiring`. Change record: ROUTE-METADATA-01; contract: route-metadata.md; existing Foundation/Routing audits and #3123/#3125 provide scope. This is the RM-04 execution prerequisite and narrow I3 adapter, not the completed HTTP bridge or whole-package convergence.

The existing KernelHandlerContainer caches provider factories, tries provider fallbacks and reflectively autowires unbound classes. Its has() constructs through get(). Canonical lookup must not reuse those policies for handlers. Kernel bindings are shared by the existing declaration, while provider singleton/bind lifetimes belong to their providers.

Foundation will expose a request-local ExplicitHandlerServices facade over only registered kernel/provider keys, using Symfony ServiceLocatorTrait rather than a second locator engine. The installed service-contracts 3.7.0 trait provides metadata-only has(), exact factory get(), circular detection and no result cache. Foundation will declare this dependency directly. Kernel factories retain their shared cache, first-provider precedence remains deterministic, and provider factory results will not enter the kernel's legacy cache. Failure of the selected binding propagates without trying another binding. Existing generic CLI get()/has() compatibility stays available. The facade carries the actual current Request; explicitly supplied execution factories can read it, without route snapshots capturing request/service state. No new provider request-scope declaration is introduced in this slice.

Routing's request-local RouteHandlerResolver will select the immutable handler from its completed snapshot by the matched route name. It checks the matched scalar controller ID against that definition, refuses early/mismatched/unknown access without service calls, maps validated builtin IDs to their existing sentinels, and resolves class/service targets only from the explicit facade. Public real methods are verified after lookup; magic __call cannot supply a missing method. It returns a callable without invoking it. Execution failures produce route/handler diagnostics without exposing factory messages or changing snapshot identity. HTTP middleware, access, parameter conversion and invocation remain in the later bridge.

Owned files: Foundation explicit facade and KernelHandlerContainer adapter, Routing resolver/error, package public surfaces and Foundation manifest, generated dependency/surface authorities, specs, focused kernel/resolver/compiler callers and this ledger. No provider migrations, deployment or live-service changes.
