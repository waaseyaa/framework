# API producer and terminal migration prerequisite

ROUTE-METADATA-01 RM-06, #3122. Base 885182c915b138a4d8e43da14eedf53ce203bba1. This is a bounded API route-path review, not a full package audit or convergence claim.

API owns exposure-driven JSON:API declarations and public/admin endpoint declarations. Foundation owns transport dispatch and middleware; existing domain routers adapt route parameters, audited account context, document/status envelopes and preconditions before invoking controllers. A stable class reference alone is not equivalent to those adapters. API provider adoption must prove the complete existing terminal path, including refusals, rather than directly invoking incompatible controller methods.

JsonApiRouteProvider currently caches live Symfony Route objects in a two-entry process-static cache, including a diagnostic closure for nonexposed entities. Its five CRUD, field-save, five translation and two workflow paths are structural declarations. EntityTypeApiExposurePolicy is finalized by normal boot. The first slice moves their sole authority into pure RouteDefinition values consumed from copied entity/exposure inputs. The bounded compatibility cache retains immutable declarations only; each replay compiles fresh Symfony routes and creates any compatibility callable at execution projection, never inside a metadata snapshot.

The opaque nonexposed response becomes a named stateless handler with unchanged 404 envelope. Metadata publishes only its class identity. Handler registration and the complete ApiServiceProvider capability adoption remain the next slice; this helper alone does not unblock canonical inspection of the API cohort. Workflow route inclusion must eventually use finalized TransitionService binding presence, not resolveOptional. Content search, catalog and MCP availability must be finalized outside inspection without changing exposure or configured-capability semantics.

Root owns the JSON:API generator, stateless diagnostic handler, focused metadata/parity/refusal tests and coupled docs for this slice. No domain-router, auth, policy, storage, workflow execution or provider capability change is included. Maintained Symfony remains responsible for compilation and matching. Existing route names/order/defaults/options/methods/requirements and compatibility constructors must remain. No new generic container or dispatch wrapper is proposed.

Acceptance: pure copied-input generation under poisoned entity/service/autoload boundaries, historical scalar field parity, exposure/ordering/custom-base/workflow controls, duplicate/malformed input refusal, immutable bounded cache with fresh live projections, and actual opaque 404 execution across principal states. Root runs focused generator and API callers, scoped PHPStan and default preflight. An independent immutable reviewer owns review. Installed sibling, full API audit, supported Linux, full provider execution adoption, Admin Surface/FETDER and CLI/Bimaaji remain open.

Entity IDs use a total string order in metadata generation and compatibility cache keys. Numeric-looking IDs such as 01 and 1e0 retain distinct deterministic positions; this repairs the former input-dependent numeric comparison tie without changing route fields.
