# Auth/OIDC route producer and execution prerequisite

Change record ROUTE-METADATA-01, RM-06. Base a67383f805d690d009973e96cd6465708cba6526. Routing owns this adapter under #3125 and #3122; Auth and OIDC retain their controllers and policies. This is a bounded migration review, not completed package convergence or installed qualification.

The existing adapter eagerly resolves twelve auth dependencies and constructs twelve controllers. Optional OIDC registration resolves five controllers and catches failures, omitting unhealthy endpoints. Discovery and JWKS are string handlers. OidcServiceProvider explicitly declares all seven OIDC controller bindings. Routing is a required auth adapter with optional OIDC distribution; it must not autoload OIDC during metadata collection.

The repair retains auth names, methods, public posture, /api/user/me priority10, composed extensions, canonical eligibility, atomic limiters, password upgrades, logging and audited internal readers. Each auth controller receives its existing constructor arguments from a nonshared explicit factory, selected only after matching. Legacy auth projection calls those same factories. OIDC's existing object-based helper remains compatible but derives its route fields from the new metadata table.

Foundation freezes explicit provider binding-key presence after boot without invoking factories. Metadata OIDC routes are included individually by these finalized presence facts, rather than successful controller construction. Declared but unhealthy endpoints remain visible and selected execution fails closed; absent bindings contribute no endpoint. No implicit OIDC autoload, credential lookup, repository query, session start or service-bus lookup occurs during inspection. Binding presence is a declaration, not a health claim. This also admits declared Discovery/JWKS handlers only when explicit bindings exist.

Root owns the adapter/helper, the narrow Foundation input projection, discriminating tests, coupled specifications and fragment. No auth/OIDC controller, credential, policy, exposure or database implementation changes are planned. Maintained Symfony compiler, matcher and explicit service locator remain the mechanism; no alternate router/container is introduced.

Acceptance: poisoned-service metadata collection, absent/partial/full OIDC binding cohorts, original route-field parity, real selected auth execution, dependency/lifetime fidelity, declared factory failures without fallback or omission, and real kernel frozen binding projection. Existing auth composition and OIDC helper tests are retained. Root runs focused integration and default preflight; an immutable independent reviewer checks the candidate. Broader tests are required only for source/base changes or unexplained failures. Linux, installed sibling floors, real FETDER, CLI/Bimaaji, the other providers and full package audits remain open.
