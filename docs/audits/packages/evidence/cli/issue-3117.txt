## Audited baseline and charter

Initial audit: Framework `5196f173b06bac698f14d292c7b827f2ddac388f`, PHP 8.5.5, native Windows, isolated worktree with candidate-local locked dependencies. No product code changed.

Observed inventory: 276 production PHP files; 28 declared providers (including the empty root provider); 30 direct Waaseyaa runtime requirements; 41 public-surface declaration entries; 146 class-level `@api` annotations without a corresponding declaration. The latter is a compatibility-disposition gap, not proof that the existing shape-based parity gate fails. A syntax inventory located 129 literal HandlerCommand declarations, not an authoritative runtime command count.

Proposed charter: CLI owns operator command presentation, parsing, discovery, transport, and composition of lower-layer operations. Storage/schema authority, authorization, lifecycle rules, and durable mutation semantics remain with their domain packages. Generation and repository-build utilities currently housed here need explicit ownership and consumer contracts rather than assumed extraction.

Inventory must include: boot-free and restricted-boot commands; normal provider discovery; optional integrations; interactive/non-interactive input; stdout/stderr and machine protocols; process exit and signal behavior; generated PHP/runtime dependencies; public extension helpers; source, split, and no-dev consumption.

## Newly reproduced boundary findings

All probes below used real classes from the exact baseline and the locked Symfony Console dependency. Provider/container fixtures are local test doubles; these are in-process boundary probes, not fresh installed-consumer or full kernel acceptance.

### CLI-IO-001: machine JSON passes through presentation normalization

- `packages/cli/src/Command/SymfonyCommandIO.php::writeln()` applies `plainText()`, which removes console-style tags.
- The real `MiscAServiceProvider` debug:context descriptor and `DebugContextHandler`, driven through CommandTester with `--entity-id=<info>literal</info>`, return JSON containing `entity_id: "literal"`, exit 0.
- A `writeRaw()` control preserves the same bytes. Several other JSON handlers use writeln; each must be traced and tested rather than assuming identical impact.
- Acceptance: preserve literal values through stdout JSON and file output where both are supported; exercise nested/non-empty values and console-tag-looking text; keep human styling separate and diagnostics on stderr.

### CLI-EXIT-001: usage status differs at handler and application boundaries

- `debug:context --relationship-counts=bad` returns 2 through CommandTester, but 1 through WaaseyaaConsoleApplication with real ArgvInput.
- `normalizeExitCode()` collapses every nonzero result except 130 to 1. The spec both promises usage/input code 2 and documents this normalization; command-level validation prose is also inconsistent with handlers returning 2.
- Acceptance: select and document one backward-compatible process contract, reconcile affected handlers/tests, prove process/application behavior for success, parser and handler validation, domain failure, exception, and interruption. Do not blindly widen all historical codes 3/4 into a new public contract.

### CLI-REG-001: rebinding a HandlerCommand loses Symfony metadata

- `HandlerCommand::withContainer()` reconstructs only constructor metadata.
- An instance with alias `audit:alias`, hidden=true, and help `Extended help` loses all three when bound. ConsoleApplicationFactory calls this on provider-returned HandlerCommand instances.
- Acceptance: preserve supported aliases, hidden/help and other explicitly supported Symfony metadata through registration, with actual list/help/invocation discriminators. Reconcile the supported extension contract before promising every mutable Symfony property.

### CLI-REG-002: service-ID HandlerCommand registration misses container binding

- The factory binds a directly supplied HandlerCommand, but returns container-resolved Command objects without equivalent binding.
- A provider yielding a service ID resolving to an unbound HandlerCommand advertises the command; invocation exits 1 with `requires a handler container` despite the handler being available in that same container.
- Acceptance: define uniform behavior for instance/service-ID/FQCN discovery, or explicitly require prebound service descriptors with early validation. Test success and missing-service refusal, and avoid false command availability.
