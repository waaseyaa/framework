What the source inspection changed

A new composer.json alone cannot deliver this. The current CLI requires page builder, SSR, SEO and workflows. The HTTP kernel constructs an API handler unconditionally. The default AI development bundle also pulls CMS packages into a normal install.

Separate CMS capabilities from shared setup, HTTP and AI tooling. Keep AI included while repairing its dependency graph. A core-only kernel test does not prove that a real app can initialize and serve requests.

AI included by default

Building the application

Both starters include maintained agent guidance, framework introspection and local AI development tools. Repair the existing bundle so the basic app gets these without CMS packages.

Running the application

Shared runtime AI contracts remain available in production. Development tooling and local-operator authority stay in development dependencies. Configure providers and models explicitly.

Creation and ordinary boot need no AI credentials and trigger no inference calls or model downloads. An explicit AI request without a provider produces a clear configuration error.

Four bounded slices

  1. Resolve ownership. Reconcile core audit ownership and trace CLI, HTTP and AI dependencies, then settle the exact minimal graph and basic manifest defaults, and reconcile the existing contracts.
  2. Qualify shared setup. Remove mandatory CMS coupling through existing providers. Prove initialization, HTTP, storage, access and default AI behavior in installed consumers, including no-dev runtime AI.
  3. Assemble both starters. Extract common files, add thin profiles and prove both app and CMS creation journeys on supported hosts.
  4. Prepare delivery. Extend the existing publication workflow and version handling. Complete the package readiness gate and publish only under later authorization, then run published-package acceptance.

Agreed

  • Basic app starter without CMS packages.
  • Shared setup infrastructure with the CMS starter.
  • AI included by default in both starters without CMS leakage.
  • Package-audit readiness under #3118 alongside installed-app qualification.
  • Plan the work before implementation.

Proposed defaults

  • Plain HTTP homepage, SQLite and PHP 8.5+.
  • No JSON:API resource layer, admin or login UI by default.
  • One CLI and HTTP kernel using optional capability registration.
  • Existing CMS package name remains.
