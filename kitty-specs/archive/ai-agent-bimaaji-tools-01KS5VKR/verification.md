## Notes for M3 (`bimaaji-mcp-bridge-01KS5VS8`)

- The four MCP tool wrappers MUST preserve every row in the contract above (name, capability, argument schema, return envelope structure). Any deviation breaks SC-004.
- The aspirational sovereignty-deny envelope `{ ok: true, data: { valid: false, denied_profile, reason } }` is **not** present in the shipped surface. `MutationResult::toArray()` returns `{status, request, errors}`; `SovereigntyGuardrails` is bound in the container but is not yet composed into `MutationValidator`. Wiring it through is a future change — when it lands, the validator's `errors` vocabulary expands but the envelope shape stays the same.
- The aspirational capability-error envelope `{ error: { code: 'capability_required', details: { required: '…' } } }` is **not** present in the shipped surface. `AbstractAgentTool::requireCapability()` returns `AgentToolResult::error(summary: 'forbidden', message: 'Account <id> is not permitted to call <capability>')`. The required capability string is recoverable from the `message`; the `summary` is the canonical signal. Future structured-envelope work can be added without breaking these contracts.
